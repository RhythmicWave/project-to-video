# 递进因果讲解模式

递进因果模式适合解释一个局部机制：从少量起点开始，按因果顺序逐步加入对象、箭头、条件和结果。它可以表现审批闸门、重试、提醒注入、事件分发、数据转换和回流，但不代替项目全景。

## 什么时候使用

使用前先问：观众是否需要看到“这一步导致下一步”的关系？如果答案是否定的，静态结构图或全景高亮更合适。适合的信号包括：

- 一个检查点会把流程分成不同结果。
- 某个对象在处理前后发生结构变化。
- 任务暂停后由明确事件恢复，或失败后回到某个节点。
- 一个横切机制在主流程中介入并改变可见性、权限或记录。

不适合用它展示大规模网状拓扑、纯目录关系或没有状态变化的模块清单。

## 七个节拍

1. 只出现触发者、目标和最小输入。
2. 加入第一个参与对象；箭头写动词，如“发起调用”“读取配置”。
3. 加入检查、转换或等待点，并保持前面元素可见。
4. 展示分支；每条分支写结果和下一步，不只写条件名。
5. 展示状态、记录、上下文或界面的可见后果。
6. 展示结果返回、恢复、重试、汇合或结束。
7. 必要时缩回全景，指出该机制在锚点主线中的位置。

每个节拍只引入一个主要因果变化。已有对象可以改变状态或内容，但不要同时新增一组未解释的对象。

## 箭头和对象契约

每条主要箭头必须有来源、目标、动作、载荷/关联 ID 和证据。动作优先使用“发起、检查、等待、批准、拒绝、写入、读取、发布、订阅、恢复、重试”等动词。实线、虚线、颜色和箭头方向的含义在同一视频内保持一致；不要跨章节临时改变。

选中、聚焦、执行中、等待和完成是不同状态。候选集合先展示数量或代表性实例，再突出选中者；选中不会自动等于执行中。等待必须能追到恢复者，重试必须能追到重新进入的节点。

决策门只表达条件判断，不自动生成业务结果。用 DecisionGate 显示条件，用 Connect 或 Transfer 连接分支；批准/拒绝、命中/未命中和成功/失败的后果由场景显式配置。

## 与全景和具体例子的结合

局部机制作为全景的一个“可定位片段”进入。可以使用 OverviewDetail、FocusTrail 或小地图，但只保留一种主要定位方式。局部展开的锚点必须经过相同的缩放和平移变换，不能用另一套近似坐标。

可以用最小教学例子降低理解成本。例子应使用稳定的对象 ID、短载荷和源码支持的结构；在复习材料中注明是教学示意。不要把示例延迟、结果或顺序扩展成项目没有的能力。

## 可复用组件

Progressive.tsx 提供：

- ProgressiveReveal：按 time、at、duration 渐入并轻微位移，所有时序由调用者控制。
- CausalStep：固定边界、标题、动作和状态的步骤卡；使用 WrappedLabel，不依赖 SVG 自动换行。
- DecisionGate：条件菱形和显式分支标签；不推导业务结果。
- ContextTransform：展示 before → 插入/改变 → after，适合提醒、系统提示、序列化和压缩。

组件只提供表达能力，不知道项目的调用关系、并发保证或事实。用 geometry.ts 的端口与坐标工具连接它们，用布局 manifest 登记边界、文字和路线。

模板中的 ProgressiveCausalDemo 和[通用预览](../assets/previews/progressive-causal.mp4)展示了两种组合：递进检查/分支，以及上下文前后变换。预览中的标签只是中性教学数据，使用项目时必须替换为源码支持的事实。

## 检查清单

- 去掉箭头和图标后，仍能用一句话说出本节因果结论。
- 每条分支都有后果和去向，没有孤立的“高风险/失败/等待”标签。
- 画面顺序和运行顺序的差异已说明；示例没有伪装成运行日志。
- 关键对象、关联 ID、字段层次和读写时机没有被过度省略。
- 最后回到全景或下一步，而不是停在一个局部结果。
