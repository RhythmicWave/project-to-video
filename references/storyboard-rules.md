# 连续分镜与动画讲解

先建立项目全景，挑出能够解释主要职责和数据去向的核心链路，写清它们互相衔接的位置。成片以理解系统为目标，复习问答用于检查覆盖。

每个关键镜头先记录学习结论、全局锚点、技术依据、可见后果及表达理由（见[讲解质量](explanation-quality.md)），再安排动作：进入原因、参与对象、开始/结束状态、后续去向和证据。简单镜头可合并记录；这些是设计依据，不是等待用户填的表格。

展示列表、消息或记录时，先判断它是实际顺序、内部字段层次还是分类示意。实际顺序用编号和方向明确表达，内部字段嵌在所属载荷中；省略的步骤和可选字段以最少标记说明。提到某个记忆、日志或配置对象时，至少交代它由谁更新、何时读取、会改变哪一步，避免只放名称。

## 先组合子流程，再安排镜头

相同触发、共享状态或构成一次完整请求/结果往返的步骤，优先组合为一个讲解单元。子流程可以嵌套；大模块包小模块只用于真实包含关系，调用展开或讲解窗口使用相应的明确标题。跨模块的交互应连回触发它的主线，不能留下只出现状态、不出现去向的旁支。

默认一条视频讲完整主线及必要支撑机制；只有认知负荷过大且可以形成独立闭环时才拆分。文档数量和共享全景都不是分片依据，先看是否属于同一任务或数据生命周期。可以连续讲清时用章节定位；确需分片时写明各自的核心结论和交接点。

跨模块衔接具体说明“哪个对象或 ID、哪些字段、由谁写入、后面谁读取、什么触发下一步”。保留示例身份，按实际读取字段移动数据；不能因两个模块都叫计数、缓存或任务，就假定它们使用相同输入或前者触发后者。调度、权限等横切保障在观众已理解被保障的业务后引入，或用必要的短前置提示定位。

## 选择叙事结构

按学习问题选择，不按源码或文档顺序固定铺开：

| 结构 | 适合解释 | 关键约束 |
| --- | --- | --- |
| 全景 → 聚焦 → 回全景 | 模块嵌套、调用链、系统边界 | 局部始终保留全局锚点 |
| 递进因果 | 审批、重试、提醒注入、数据变换 | 每次只新增一个因果动作 |
| 前后对照 | 压缩、装配、序列化、上下文变化 | 前后对象身份和字段关系一致 |
| 并行对照 | 同步/异步、多个实例、成功/失败分支 | 明确是否真实并发和汇合条件 |
| 先结果后回溯 | 先展示用户看到的结果，再解释内部原因 | 回溯路径要回到同一个关联 ID |
| 横切叠加 | EventBus、Trace、权限等观察/控制机制 | 叠加线不能冒充主调用线 |

每次换视角保留至少一个稳定锚点：任务 ID、对象身份、全景位置或同一载荷。展示顺序与运行顺序不同时，在画面或内部设计记录说明；没有清楚锚点时保留线性片段。

跨模块主线可用“全景定位 → 局部机制 → 动态全景回挂”：结尾选少量已讲技术锚点，跟随一条代表数据流返回原对象及连接。它用于把局部理解接回整体，详见[开头定位与结尾动态回挂](explanation-quality.md#开头定位与结尾动态回挂)；短流程已保持共同对象时，无须增加独立回顾章。

保持全片的空间或身份连续性。可选用：全景缩到角落后展开子系统、摄像机沿请求移动、组件打开暴露内部、同一载荷被解析或装配、任务挂起而旁路继续、历史条目收拢成摘要。根据机制选择表达，不要求所有镜头使用同一种过渡。

避免只让连线闪烁。消息到达要产生可见后果，例如请求展开字段、Agent 改变状态、文件抽屉增加一行、工具箱打开后产生结果、旧上下文收缩。保持简短标签与动作一同出现，长篇实现细节放在证据笔记。

默认无配音时，每个新关系留足观察时间。镜头移动只用于定位，避免边移动边读长句。一个节拍突出一个因果变化；同时发生的动作必须有源码中的并发依据。运动时长是教学节奏，若无运行记录不能作为性能数据。

项目示例从源码支持的路径构造，不把示意结果写成运行日志。条件分支用“需要审批时”“达到阈值时”等短语，不在画面中加入执行状态免责声明。全景图为认知地图时，明确哪些连线表示调用，哪些表示观察或数据依赖。

制作时优先检查过渡帧、输入输出身份、动作发生顺序及对象遮挡。完整片段的观看结果比单独静帧更能判断讲解是否连贯。

## 详略与注意力

先写出贯穿全片的两三句因果解释，再判断每段是否帮助补全它。主链路使用最多的展示时间，支撑链路通过具体问题引入，旁支机制放进配套索引。每个时刻保留一个主要变化：当前对象高亮，相关对象可见，背景对象降调。长方法名、协议字段和异常码只在影响理解时进入主画面。

字幕应说明正在出现的变化，不能抢先描述尚未展开的结果。镜头缩放期间避免添加新关系；先定位，再展开，再观察后果。示意粒子沿可见的路径运行，路径交叉时明确归属。一次教学抽象省略了步骤，就用短提示说明范围，不凭完整任务标题暗示所有工作已经被实际展示或执行。

需要把局部机制从零建立起来时，按[递进因果讲解](progressive-causal.md)的节拍组织：起点 → 动作 → 检查/转换 → 分支 → 可见后果 → 返回/汇合。每个节拍只引入一个主要因果变化；不要把多个未解释的框和箭头一次性淡入。
