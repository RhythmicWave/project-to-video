# 讲解完整性、示例与视觉一致性

分镜规划与局部复核都使用本页的判断框架；具体表达按机制选择，优先解决影响因果理解的缺口。

## 从“有名字”到“讲明白”

系统总览必须展示真实参与者、状态系统及主要连接；章节名称排成一行不能承担总览。跨模块关系较多时，局部展开保留同源缩略图并高亮当前对象，或通过连续镜头保留同等清楚的定位。不要每章重画互不相连的小流程。

主视图用可辨识对象、载荷、代表性记录及状态前后变化解释机制。暂时隐藏字幕后，应仍能看出输入来自哪里、谁改变状态、结果去往哪里。必要的类型、方法、SQL 条件、缓存键和脚本名称在对应局部展开；决定原理的实现细节不能全部转入笔记。并发要明确外层和内层、先后条件及各自汇合点。

## 根据镜头任务决定详略

| 层次 | 当前要让观众理解什么 | 保留 | 后置 |
| --- | --- | --- | --- |
| 全景 | 核心职责、架构分层、状态归属与主要数据去向 | 代表类型或简短角色名、Handler/Service/Repository 等关键依赖层级、系统边界和连接 | 方法清单、字段、脚本、缓存键、细碎配置与次要子类型 |
| 子流程 | 谁调用谁、如何到达结果 | 当前参与类型、对应动作与返回/分支 | 不参与当前因果的类型和配置 |
| 机制展开 | 为什么正确，关键条件怎样改变结果 | 必要字段、SQL/Lua、状态前后值及不变量 | 完整函数体、所有边界、低频配置 |

先写一句镜头要传达的认知，再决定标签。全景应让观众看出有技术含义的依赖结构，例如入口校验、业务服务、仓储和外部存储；只保留“处理/入口”会丢失架构层次。采用少量代表类型、层级列标题或清楚的模块边界即可，不要求为每个节点再加方法行。总图与局部通过稳定对象身份关联，允许仓储在全景显示简短业务名、在局部展开具体实现。缩略图沿用全景的信息层次。具体细节围绕当前认知进入画面，一个标签若不帮助当前判断，就折叠或后置。

决定一个细节是否进入当前镜头，可以问：隐藏它之后，观众是否会误解对象职责、运行顺序、状态所有者、分支条件或结果？会则在局部保留；只是提供实现入口则用一条代表符号，其余放笔记。全景的技术含义由真实层级、少量代表类型和状态系统承担；具体方法解释当前动作，SQL/Lua与字段解释机制为何成立。

以中性缓存读取为例：全景展示 RequestHandler → ResourceService → CachedRepository 及独立的缓存/数据库连接；子流程在对应对象处展开 Get(id) 与 hit/miss；机制镜头用一个稳定 ID 展示 miss → DB 返回 → 回填，以及返回与写入的完成边界。一次镜头所讲的结论决定详略，三层可分镜也可连续缩放，项目不必套用这些类名或缓存机制。

## 让设计选择可检查

关键镜头用一条简短记录说明：学习结论、全局锚点、技术依据、可见后果、表达方式及理由。技术依据应是当前镜头需要的真实类型、方法、协议、脚本或条件；复制完整签名通常不能增加理解。

| 需要观众判断 | 优先让画面发生什么 |
| --- | --- |
| 系统整体怎样组成 | 参与者、分层和状态系统留在一张关系图；按一条任务改变注意范围 |
| 请求和数据怎么走 | 载荷移动后接收者开始动作，生成结果或返回分支 |
| 为什么条件改变结果 | 展开最小字段/条件，展示前后值及分支去向 |
| 多个工作如何协调 | 保留候选或分支集合，表现选择、等待、恢复与汇合 |
| 同一对象如何被处理 | 保持 ID、形状和字段归属，变换或写回内容 |

文字框适合条件、记录、代码片段或真实面板；运行参与者使用合适的轮廓，数据容器体现其状态所有权。图标本身只解释对象身份，需由载荷、字段、集合变化和完成后果形成机制。不同技术问题可以选择不同表达，稳定风格和对象身份比统一排成一列更重要。

| 情况 | 画面至少交代什么 | 可选表达 |
| --- | --- | --- |
| 多实例选择一个 | 候选集合、选择依据或目标 ID、选中者、输入去向 | 保留其余实例降调，选中描边/勾选，载荷送入该实例 |
| 忙、等待、失败 | 当前状态的后果；输入被拒绝、排队或继续；谁触发恢复 | 返回分支、真实队列、暂停点与恢复信号 |
| 记录或存储 | 谁产生内容、代表性字段、怎样写入、何时被谁读取 | 展开一条记录、追加一行、读回目标 |
| 提示词/配置/记忆 | 来源、组装顺序、加载时机、是否即时更新 | 分层组装、快照与下一轮读取 |
| 协作或扩展机制 | 入口是什么、由谁解释、控制何种行为、结果返回哪里 | 指令展开、调用返回、父子局部视图 |
| 并发与汇合 | 哪些工作可以重叠、各自状态、汇合条件 | 独立泳道；全部等待、首个完成或无汇合需按源码选择 |

选中、聚焦、执行中是三个不同含义。只显示一个带编号的对象会让人猜测实例数量；若数量不是重点，可用两个代表实例并说明省略，不必穷举全部。高亮其他对象不等于它也在执行。

同屏摆放不证明并发，调用展开不证明所有权，文件出现在某个目录不证明隔离保证。存在上下行不同通道时，分别连接实际端点，再用身份关联，而不是笼统画成双向箭头。

事件总线要拆开判断三层语义：多个生产者或任务是否能并发产生事件；一次 publish 是否按注册顺序逐个 await 订阅者；订阅者内部是否把事件放入队列后异步处理。只有源码出现 create_task、独立队列或明确的并发调度时，才把并行画成同时推进；多条订阅箭头本身不代表 fan-out 并行。

每段围绕“输入 → 状态变化 → 后果 → 下一步”闭合。多个片段共同解释一个机制时，保留共同对象或载荷，不让补充机制成为孤立小插曲。过多细节影响主线时，把必要边界转入笔记并给出索引。

## 修订时保留已有理解条件

先确定反馈影响叙事、详略、表达、时序还是渲染，再修改对应层。压缩标签时保留架构层级与决定结果的条件；增加技术依据时只展开当前判断需要的符号。先复核改动最密集的镜头及一个关联转场，确认核心结论、全局定位、技术依据和可见后果同时成立，再导出完整片。无需每轮重新询问已经明确的偏好。

## 用具体例子解释抽象机制

可以构造一个最小、合理、源码支持的任务贯穿链路。例如用一条请求展示选择实例、处理、写入和返回，再按需要展开条件分支。例子是教学输入，不要求是真实执行记录。

- 示例性质在复习材料或内部检查中说明；画面只保留理解逻辑所需的对象、状态和动作标签，不重复执行状态免责声明。
- 示例 ID、数据、时间在全片保持一致；请求、响应、工具结果和记录用相同关联关系。
- 结构和顺序必须真实：字段嵌在其所属对象中；若是类别列表而非执行顺序，要改变布局或明确标记。
- 可以压缩等待时间、缩小数据量、略去重复项，但不得省略会改变结论的条件、边界或分支。
- 样例延迟、吞吐和结果不得当作实测成绩；未实现能力不能借例子暗示已存在。

## 新组件接入现有风格

先看资源演示、Systems.tsx 和 theme.ts，再决定复用、局部适配或新增。新组件对齐当前项目的字体层级、主色/状态色、描边粗细、圆角、阴影强度、视角和运动节奏；优先复用 Label、Transfer、端口函数及现有材质。

不同对象应有可辨识轮廓，同类对象保持相同结构。不要混用写实图、表情字符、不同风格图标库与线稿，除非场景明确需要这种区分。颜色配合文字、形状或线型，避免只靠颜色表达状态。

新增图标只实现当前语义需要的状态，并检查大图与缩略图。把图形、状态和时序分开：图形识别职责，执行环来自处理事件，聚焦用区域或外部轮廓。状态动画必须有含义；不为所有对象加入持续转动或脉冲。

## 连线和版面如何自检

对象布局确定后，以图形边界端口产生连线。连线、箭头和移动标记共享路径；父级缩放/平移后，锚点必须经过相同坐标变换。图形的标签区单独留白，连接对象图形而非文字。`geometry.ts` 提供边界端口与坐标转换，自动避障仍由场景负责。

为标题、导航、主视图、图标及其标签、短提示分别预留空间。容器边界计入标题和底部标签；隐藏内容确实退出主注意区，避免多个半透明标题叠在一起。SVG 组不会自动裁剪子元素，局部视图要明确内容范围，确有需要时设置 clipPath。

检查目标分辨率下的最长真实中文/英文标签、最大可见条目数、最深必要层级和状态变化后的文字。不要单纯缩小字体塞满画面；先缩短标签、分节拍、折叠次要层级或扩大局部视图。

除静止画面外，检查转场开始/中间/结束、载荷到达、等待→恢复、分支→汇合、对象重新排列与长标签出现的时刻。连接端点与移动轨迹一致不等于线路没有穿过别的内容。类型检查、文件检查和抽帧脚本都不能替代视觉判断；用户承担观看时，把这些时刻交给用户并如实记录验收状态。
