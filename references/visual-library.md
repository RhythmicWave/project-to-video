# 视觉资源分层

围绕“表现什么”和“如何随时间变化”划分资源，按需要组合。

| 层级 | 内容 | 典型实现 |
| --- | --- | --- |
| 基础绘制 | 文字、路径、形状、轨迹、遮罩、高亮 | 绘制组件、插值与几何函数 |
| 系统表达 | 参与者、资源、边界、连接及状态 | Agent、终端、存储、模型、协议关系 |
| 行为模式 | 多个对象随时间协作 | 请求返回、等待恢复、广播、摘要转换 |
| 讲解场景 | 把机制组合成连续认知 | 全景进入局部、跟踪任务、比较执行前后、全景合流 |

颜色、字体与线型是跨层视觉规范。项目事实、业务名称、实际流程和证据属于项目数据。接口按层设计，行为模式可以是事件序列或编排函数，场景可以由多个组件组合。

## 语义映射

Agent 是参与者，其目标、状态与工具范围可逐步展开。存储是资源，写入、读取及回放是发生在资源上的行为。异步通常用“某个任务挂起，其他任务仍能推进，恢复事件使原任务继续”来表达。需要讲解 Future 的内部状态时，才将它作为 pending/resolved 对象。

每个资源描述实现路径、可配置参数、预览、适用条件和限制。只有名称或设计建议时，将其视为候选，不当作已有可运行组件。

## 动画讲解能力

- 保持全局位置：从全景进入局部时保留空间或身份关联，可使用全局缩略图、边界展开、连续缩放或路径追踪。
- 保持任务身份：同一消息在装配、调用、结果回填中可被持续认出。
- 显示真实变化：事件到达后界面改变、存储写入后条目增加、压缩后消息减少、审批返回后任务恢复。
- 镜头与短提示同步：提示当前画面正在发生的因果关系，给观察和理解留下停顿。
- 使用状态与时间解释并发，不让一组同时移动的标记暗示实际不存在的并行或一致性保证。

## 边界与流向

嵌套用于表达明确层次：进程中运行哪些组件，一次调用包含哪些执行步骤，容器中保存哪些数据。分别用标题、边界样式或视图切换说明。对象在某函数内创建不等于它拥有所有共享依赖；外部服务仍应在对应进程边界之外。

请求、响应、事件与持久化使用一致的视觉语义，并保留方向箭头。审批等交互可能下行走事件推送、上行走 RPC 命令；把两条路径连接到相同关联 ID 的等待状态。等待用暂停位置和恢复触发表达；顺序规则可用紧凑时间条。若源码没有业务队列，就不能通过排列和移动条目暗示排队机制。

资源的形象服务于认知。能用简短状态、路径或时间条说明的机制，无需增加拟物对象或持续动画；没有状态含义的转动、脉冲和粒子应控制在低优先级。

项目中新设计的资源先在项目工作区验证。正式共享库只复用已有明确实现；扩展遵循当前项目需要和用户授权。

## 已提供的可选资源

| 层级 | 资源 | 使用条件 |
| --- | --- | --- |
| 基础绘制 / 系统表达 | [图标与载荷](visual-components.md) · Agent、Archive、Terminal、Model、Toolbox 等 | 需要清晰区分参与者、存储、服务、工具与数据 |
| 行为模式 | [时序与循环](visual-components.md) · Transfer、AwaitResume、PhaseLoop | 传递、等待恢复与迭代；由项目明确给出路径和时序 |
| 讲解场景 | [逐层聚焦导航](focus-navigation.md) · FocusTrail | 全景与多层细节之间需要持续定位；路径由项目确定，可替换为其他导航 |
| 系统表达 / 讲解场景 | [候选选择与局部展开](composition-patterns.md) · InstanceSelection、OverviewDetail | 多实例定位、保持全景身份后进入细节 |
| 行为模式 | [并行泳道](composition-patterns.md) · ParallelLanes | 独立推进与按条件汇合；需有并发依据 |
| 行为模式 / 讲解场景 | [递进因果](progressive-causal.md) · ProgressiveReveal、CausalStep、DecisionGate、ContextTransform | 逐步建立局部因果、分支和前后结构 |

资源是可选择的表达能力。根据项目真实结构和认知负担组合，不把示例的树形、布局或配色当作所有视频的固定版式。
