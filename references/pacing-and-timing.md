# 节奏与阅读时间

无配音视频需要同时看清动作和读懂解释。把**动作时长**、**结果观察时间**和**字幕阅读预算**分别设计；缩短重复停顿时，也要检查是否造成局部一闪而过。

## 三个档位

`assets/remotion-template/src/visual/pacing.ts` 提供三个起点，单位都是秒：

| 档位 | 适合场景 | 典型动作时长 |
| --- | --- | --- |
| `fast-review` | 用户已经看过项目，快速回忆主线 | 出现 0.42，淡入 0.40，聚焦 1.35，结构变化 1.45 |
| `balanced` | 默认复习和第一次完整观看 | 出现 0.55，淡入 0.50，聚焦 1.70，结构变化 1.70 |
| `spacious` | 信息密度高、中文标签较长或需要教学停顿 | 出现 0.72，淡入 0.65，聚焦 2.10，结构变化 2.10 |

这些数值是起点，不是整片的倍速。每个项目仍应根据标签长度、画面复杂度和因果难度微调。

`Transfer`、`Along` 等载荷移动的起止时刻通常由具体链路决定，不直接套用全局档位；它们要同时满足“观众看出从哪里到哪里”和“到达后能读懂状态后果”。

## 怎么调

1. 先定位过快或过慢的具体节拍，保留已经合适的区间。分别调整传输、处理、转场或阅读预算；整片倍速会同时改变正常区间和无配音阅读时间。
2. 一个状态变化完成后，至少保留一个观察节拍。简单图标通常约 `0.5–0.7s`，带有中文字段、分支结果或前后对照时约 `0.8–1.2s`；这是教学停顿，不是性能数据。
3. 只在连贯的动作属于同一因果变化时加速。审批、等待恢复、并行汇合、写入后读回等边界不要为了节奏省掉恢复者、汇合条件或结果去向。
4. 局部 `duration` 可以覆盖档位。复杂全景进入局部通常 `1.4–2.0s`；递进步骤出现通常 `0.4–0.7s`；结构前后变换通常 `1.4–2.1s`。镜头移动本身不应承载长句阅读。
5. 片尾或章节切换需要保留定位时间。若只是让过渡更快，优先改过渡参数；只有确认章节内容已经过长，才同时调整章节时间、索引和复习笔记。

## 验收节拍

长折线路径、跨区移动或新载荷标签要按实际屏幕距离检查速度。首次出现通常可从 0.9–1.2 秒的传输开始，长路径再增加；连续 0.2–0.3 秒的处理节点接短传输，会使多个步骤难以分辨。时间是教学呈现，不是后端延迟。对已经清楚的动作保留原参数；复杂字段和结果可增加观察预算。

### 字幕预算与停顿压缩

可用 [pacing-budget.mjs](../assets/remotion-template/src/visual/pacing-budget.mjs) 的 `estimateReadingSeconds` 作为初筛：按中文密度、技术词和定位开销估算，允许在 cue 元数据中用 `readingSeconds` 覆盖。调用 `captionReadingWindows` 时传入由事件解析后的 cue；原始节拍不足会报错，需要先延后编排或缩短文字。

阅读预算包含字幕区间内的动作时间；公式不判断画面密度，首次出现的字段、SQL 和复杂并发需结合代表片段增加预算。导出时的静止段压缩与 `budgetStaticRuns` 用法统一见[高效渲染](render-efficiency.md)。

编码后重新检查每条字幕的**实际时长**，覆盖最短区间、长技术句、连续步骤和章节尾部。冻结检查发现长静止，字幕检查发现过快，两者共同使用；不能把“无长冻结”当成节奏合格。测试入口为 `npm run check:pacing`。

对每个重要动画检查进入帧、中间帧和结束帧：

- 进入帧只出现应当出现的对象，标题和路径没有抢先跳出。
- 中间帧能看出对象正在改变什么，移动载荷与线路、箭头端点一致。
- 结束帧显示状态后果，并留下足够时间读标签；等待、分支和并行场景还要确认谁恢复、谁汇合、谁继续。

如果画面在结束前就切走，先延长观察停顿或缩短标签，再考虑放慢动作。若动作结束后仍拖沓，先缩短重复停留或拆分长字幕；需要展示处理中时，让进度或状态随真实处理事件改变。停顿与渲染效率检查见[高效渲染](render-efficiency.md)。
