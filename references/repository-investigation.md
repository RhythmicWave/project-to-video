# 从源码理解项目

先识别入口、运行进程、状态所有权、协议及外部依赖；再从真实触发点跟踪关键行为直到结束和持久化。文档用来定位，源码和真实测试结果用来确认。探索视角和主线选择见[项目探索与主线选择](project-exploration.md)。

## 起点与并行分工

先阅读 README 并检查其命令、模块描述是否仍适用。缺少 README 时在产物目录建立概览继续；用户要求补建业务 README 时，写简洁的项目定位、运行入口、主要模块和已知限制，分镜保留在视频资料中。

用 `rg --files` 寻找依赖清单、启动入口、协议/类型定义、数据模型和测试。按依赖关系自适应深入，无需扫描或读完每个文件。

并行调研最多主 Agent 加两个子 Agent。一种可选分工是主 Agent 跟踪主请求链，子 Agent 分别研究状态/持久化与事件/后台任务；按真实项目边界调整，避免仅按语言或目录平分。小项目可以顺序完成。

分工前统一任务清单和术语。子 Agent 只读指定范围，不改业务代码、不继续委派；输出触发、输入、关键动作、状态所有者、结果、重要分支、证据及疑点。主 Agent 核对跨边界调用双方，将结果按任务链合并到同一 system-map.md，保留冲突；不按目录或 Agent 顺序拼成分镜。候选流程与主线取舍统一见[项目探索](project-exploration.md)。

## 链路核查

从一条具体任务追到结果，核对请求与响应、事件的发布与订阅、异步等待与恢复、数据写入与读取。存在多条通信路径时分别画清方向、载荷与关联方式，不能根据模块名推断它们共享某个通道。

“忙”“等待”“完成”等状态必须有结果含义：新输入会被拒绝、排队、覆盖还是并发处理，数据存在哪里，谁触发下一步。协议画面需要核查实际序列化和接收解析两端，特别是 ID 与参数字段所属层级。

记录每条重要结论的文件、符号或行号，以及证据类型：

- 源码确认：已经读到对应路径。
- 测试支持：已读到断言，可说明该测试验证的范围。
- 执行验证：本次命令及结果已记录。
- 推断：当前实现强烈暗示，但缺少直接证据。
- 待确认：仍有不同解释。

重点核对常见混淆：异步与并行、await 子协程与 Future、文件存在与事务保证、进程存活与任务恢复、缓存配置与实际生效、模型建议与真实执行、事件记录与模型历史。

事件总线要拆开判断三层语义：多个生产者或任务是否能并发产生事件；一次 publish 是否逐个调用并等待订阅者；订阅者内部是否入队后再异步处理。源码确认独立调度且执行可以重叠时，才让对应泳道同时推进；入队不等于处理完成，多条订阅箭头本身不代表并发广播。

每个主链路确认正常路径与会改变结论的重要分支。资料不足时补查协议、状态迁移、测试夹具、调用点及清理路径；仅在必要时执行聚焦测试，不为视频修复无关业务逻辑。

资料冲突时记录真实实现及其限制，采用用户明确选择的讲解基准（见 SKILL.md）。排除密钥、完整环境文件及用户私有数据，使用最小示意输入。
