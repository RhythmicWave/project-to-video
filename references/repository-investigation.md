# 从源码理解项目

先识别入口、运行进程、状态所有权、协议及外部依赖；再从真实触发点跟踪关键行为直到结束和持久化。文档用来定位，源码和真实测试结果用来确认。完整的五遍探索和主线选择见[项目探索与主线选择](project-exploration.md)。

## 起点与并行分工

先阅读 README 并检查其命令、模块描述是否仍适用。缺少 README 时遵循 SKILL.md 中的询问约定；获得补建授权后，基于核查结果写简洁的项目定位、运行入口、主要模块和已知限制，不将视频分镜放入业务 README。

用 `rg --files` 寻找依赖清单、启动入口、协议/类型定义、数据模型和测试。按依赖关系自适应深入，无需扫描或读完每个文件。

并行调研最多主 Agent 加两个子 Agent。一种可选分工是主 Agent 跟踪主请求链，子 Agent 分别研究状态/持久化与事件/后台任务；按真实项目边界调整，避免仅按语言或目录平分。小项目可以顺序完成。

子 Agent 收到明确范围和证据输出约定：职责、入口、关键路径、状态所有权、源码位置及疑点；不修改业务代码，也不自行继续委派。结果由主 Agent 合并到同一份 system-map.md。跨边界问题仍要由主 Agent 读取调用双方核对，不能直接拼接各自的结论。

并行调研之前，主 Agent 先给出任务清单和共享术语。子 Agent 输出入口、触发、关键动作、状态所有权、结果去向、一个边界分支、证据和疑点，不要只返回文件摘要。主 Agent 合并时按任务链重排结果，保留冲突，不按子 Agent 的目录顺序直接写成视频。

## 先找流程，再找模块

用用户可感知的动作或协议触发点命名候选流程。每条流程必须有正常结束或明确的等待/失败结束；只出现“初始化”“管理器”“服务层”的候选不能直接进入分镜。至少选一条正常路径和一条改变控制流、状态或持久化的分支，除非项目证据表明不存在此类分支。

## 链路核查

从一条具体任务追到结果，核对请求与响应、事件的发布与订阅、异步等待与恢复、数据写入与读取。存在多条通信路径时分别画清方向、载荷与关联方式，不能根据模块名推断它们共享某个通道。

“忙”“等待”“完成”等状态必须有结果含义：新输入会被拒绝、排队、覆盖还是并发处理，数据存在哪里，谁触发下一步。协议画面需要核查实际序列化和接收解析两端，特别是 ID 与参数字段所属层级。

记录每条重要结论的文件、符号或行号，以及证据类型：

- 源码确认：已经读到对应路径。
- 测试支持：已读到断言，可说明该测试验证的范围。
- 执行验证：本次命令及结果已记录。
- 推断：当前实现强烈暗示，但缺少直接证据。
- 待确认：仍有不同解释。

重点核对常见混淆：异步与并行、await 子协程与 Future、文件存在与事务保证、进程存活与任务恢复、缓存配置与实际生效、模型建议与真实执行、事件记录与模型历史。

每个主链路至少确认正常路径和重要条件分支；对缺失文档的项目读协议/类型、状态迁移、测试夹具、调用点及清理路径。只有必要时执行聚焦测试，不为视频修复无关业务逻辑。

资料冲突时记录真实实现及其限制。排除密钥、完整环境文件及用户私有数据，使用最小示意输入。
