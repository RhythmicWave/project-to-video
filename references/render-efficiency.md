# 高效渲染与停顿检查

适用于由 SVG/React 重建系统图、存在明确动作和观察区间的无配音动画。包含视频素材、连续粒子或无法证明静止的场景，仍按正常逐帧渲染。

首次长导出前，选一个包含真实文字密度、状态与转场的片段，记录绘图、编码与拼接耗时。纯 SVG 可试原生路径，HTML/CSS 或媒体场景继续使用浏览器；编码器先在目标尺寸启动验证。依据瓶颈选择方案，再扩展完整视频。渲染规格与视频的教学时长分开：30fps 成片仍可复用静止代表图。

1. 先做关键机制和转场的 720p 预览；核对方向、标签、状态与完整因果后再正式导出。使用已安装的渲染浏览器可避免首次下载等待，不改变浏览器 UI 的用户选择。
2. 显式记录动作区间与观察区间。帧函数在观察区间保持同一状态；正式运动按目标 fps 绘制，静止只绘制代表帧。用 `renderFrames` 的 frames 数组选帧，再以 FFconcat 的 duration 和 CFR 编码恢复目标 fps。输出 30fps 不等于必须重新截图 30 次/秒。

   涉及先后和并发时，从[因果时间轴](causal-timeline.md)编译结果生成动作区间和状态边界。让帧函数持续读取 frame/fps；固定的“字幕之后几秒”采样与场景时间截断会漏掉因依赖而延后的动作。处理进度会变化时，给对应任务声明 motion=true。
3. 按章节保存截图、片段、进度与规格检查。缓存键包含相关源码、依赖、输入、尺寸、帧率和渲染参数；相同输入可续跑和复用。若缓存键覆盖全片源码，不要声称任何修改都只影响单章。局部修正可单独渲染受影响章节，再验证并合成。

   高迭代频率时，将局部机制拆成独立模块；用章节本身、共同依赖和输出规格生成章节缓存键。每章从局部帧 0 渲染，避免前一章时长变动导致后续截图重新命名。模块依赖闭包要真实，不能遗漏间接依赖；字幕或方法改动应只影响对应章节，共享全景、主题或渲染器变化则合理影响所有相关章节。通过一次局部改动验证“本章失效、其他章复用”。
4. 动作结束后的停顿按阅读密度设计，通常约 1–2 秒。超过 3 秒的静止区间逐段检查：长字幕先缩短或拆节拍，重复画面可缩短。不要靠无意义脉冲掩盖停顿，也不要整片倍速。
5. 自动缩短须证明画面不变，例如连续 JPEG 字节相同；小的渲染差异可能使这个检测漏掉停顿，需额外检查编码后实际冻结区间。删除静止尾部，保留动作原速及必要观察时间。
6. 维护原始帧→实际输出帧的时间映射，生成实际 chapters.json 和字幕。章节拼接后核对总帧数、尺寸、CFR、编码及音轨；README、笔记和问题索引必须使用实际输出时间。

先汇报实测渲染帧数、复用量、耗时及输出时长，再讨论提速幅度。并发数量按实际内存与 Chrome 进程负担调整；少量并发常比占满全部逻辑核更稳定。

纯 SVG 图形可采用[原生 SVG 渲染](native-svg-rendering.md)减少浏览器截图开销。硬件编码加速的是图片到视频这一步；若主要耗时在绘图，单独换编码器不会同比改善全流程。
